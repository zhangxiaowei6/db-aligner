# 前端开发与交互规范

## 适用任务

用于页面功能、连接树、同步范围、差异详情、编辑弹窗、主题和预览行为的开发与修复。
仅修改文档时核对相关行为即可，不因此启动界面验收；跨进程契约变化同时使用
`protocol-change`，验证组合使用 `verification`。

## 操作流程

1. 从页面事件追到控制器、模型及接口，确定修改的是本地草稿、自动加载还是明确提交；核对现有测试后再修改。
2. 复用 `DataTable`、选择切换按钮和现有表单组件；后台请求按钮使用 `AsyncButton` 跟踪实际 Promise，刷新复用现有持久反馈。不要由处理函数用 `void` 丢弃请求。
3. 用 `copyModel` 分离已保存模型与编辑草稿，接口参数通过现有 `api` 转为普通 JSON；结合请求标识、工作区和编辑会话检查过期结果。
4. 修改范围与业务行为时同步核对浏览器预览；新比较保持结构或数据单一类型，数据模式按目标跳过缺表。旧混合模板的应用和编辑继续保留既有兼容提示。
5. 按受影响交互补充有意义的测试，更新交互文档、相关截图和设计记录，执行对应验证。

## 关键约束

- 保持白／灰／蓝风格，支持浅色、深色和跟随系统；使用主题能力，不以硬编码浅色背景覆盖深色主题。
- 所有支持 placeholder 的输入与选择控件必须提供具体中文填写／选择提示，覆盖新建、编辑、导入、搜索及筛选；提示不替代标签、必填与格式规则，并保留已有值和已存密码提示。复选框、单选框、开关等无原生 placeholder 的控件使用清楚的标签及帮助文案，不伪造属性，细则见[表单提示](../../../docs/interaction-guidelines.md#表单提示)。
- MySQL 与 PostgreSQL 使用不同轮廓的类型图标，并保留数据库类型文字；不能仅靠颜色区分，保持浅色／深色主题可辨识。
- 表格与 SQL 区在容器内滚动，底部主要操作保持可达；表格行点击查看与执行勾选分开。管理页只由明确的编辑按钮打开编辑弹窗。
- 筛选只影响展示，不改变已选范围；全选覆盖当前筛选结果的全部分页，部分选中时补齐选择，空列表禁用。
- 保存失败保留草稿；取消、切换工作区或重开弹窗后，迟到的保存、测试和表清单响应不得覆盖新状态。记录脚本切换同样不能显示上一记录内容。
- 每个请求操作独立显示加载并防止重复提交；刷新结果保留到再次刷新，至少展示 300 ms 加载，成功／失败通过文字、图标、提示和状态播报表达。
- 两种保存模式均先确认实际来源、目标、范围及完整已选 SQL；取消不创建任务或记录，确认期间范围改变要求重新确认。
- 比较任务可跨页面查看和停止；取消请求不等于已停止，核验终态前不解锁范围。保留事件订阅清理和状态查询兜底。
- 连接树保留虚拟滚动、按需重新查询、键盘和拖拽行为；刷新失败保留上次成功清单。拖拽指示器由树组件管理，结束后清除。

## 验证与交付

- 代码修改运行 `npm run typecheck`、`npm test`；界面验收先运行 `npm run build`，再运行 `npm run qa:ui -w desktop`。
- 连接树行为涉及大清单或组织拖拽时，按需追加 `npm run qa:tree -w desktop` 或 `npm run qa:ui -w desktop -- --tree-organization`。
- 原生窗口、主进程外观或桌面桥接行为变化时，准备可用引擎构建，再运行 `npm run qa:desktop -w desktop`。
- 核对浅色／深色、最小窗口、长内容滚动、底部按钮可达及受影响键盘操作；查看生成截图，不只读脚本退出码。
- 表单变更核对空值、默认值、已有值与已存密码状态，检查所有支持 placeholder 的控件均有具体提示；数据库类型展示变更同时检查图标轮廓和类型文字。
- 交付说明列出行为变化、实际命令、报告和截图，以及未覆盖项。预览使用虚构数据，不能证明真实连接或同步成功。
