# 架构与证据模型

## 软件更新与任务互斥

软件更新由 Electron 主进程的 `electron-updater` 管理，来源固定为公开 GitHub Releases，客户端不携带发布 Token。安装版启动后延迟检查一次，用户确认下载及重启安装；不自动下载、不在普通退出时安装。生产仍加载本地打包资源，不启动 HTTP 服务；更新通过出站 HTTPS 获取软件，不上传业务资料。

主进程对业务 invoke 计数，在更新安装前冻结新入口。存在请求或超时结果不明时拒绝安装；请求超时不表示引擎工作已取消。Java 用共享／独占请求锁协调更新准备，异步比较、取消和同步任务另外检查仍活动的注册项，包含排队及执行资料收尾。只有原子确认空闲后才拒绝新业务请求并等待 Java 正常退出，再启动安装器；更新路径不强杀引擎。准备失败恢复入口，无法恢复时保持冻结并提示重新启动。

升级不改变 `io.dbaligner.desktop`、`db-aligner-desktop` 资料身份与 Windows 密码加密方式，不迁移或删除连接、SQLite、记录和恢复档案。NSIS 安装版通过同目录卸载程序标识识别；无需安装 ZIP 使用完整目录手动替换。开发、预览和 smoke 不做真实更新检查；预览仅演示状态。远程发布和验收边界见 [GitHub 构建与发布](releasing.md)。

## 进程与安全边界

React 渲染进程通过上下文隔离的 preload 访问限定接口。Electron 主进程管理系统加密密码、导入文件内容、原生文件对话框与 Java 子进程。生产只加载本机打包资源，禁止新窗口，渲染进程禁用 Node、启用 sandbox。产品不启动本地 HTTP 服务。

Java 使用 Spring Boot 非 Web 模式，stdin/stdout 每行一条 UTF-8 JSON。日志只写 stderr，由主进程追加到 `engine.log`。Windows 下协议输出明确写 UTF-8 字节，避免控制台编码破坏中文。主进程每次请求在内部传递凭据，查询返回不包含明文密码。

DBAligner 的 Java 包名与入口为 `io.dbaligner` 和 `io.dbaligner.EngineMain`，Maven 坐标为 `io.dbaligner:db-aligner-engine`，安装应用 ID 为 `io.dbaligner.desktop`。正常生产资料使用全新的 `%APPDATA%/db-aligner-desktop/data`，需要重新配置连接；不迁移或删除旧应用的档案与密码材料。IPC 通道、桥接与配置／脚本包格式标识分别使用 `dbaligner:*`、`window.dbAligner` 与 `dbaligner-*`。指定 `DB_ALIGNER_HOME` 时，业务资料与 Electron 配置分别位于指定目录及其 `electron-profile` 子目录。

SQLite 使用 WAL 与 FULL 同步保存实体、计划、记录、事件和版本链接。归档目录保存不可变原始计划、勾选、SQL 和后续证据；任务步骤状态和关联核验以追加信息保存。记录摘要不加载大型行证据，详情按需读取。

## 比较

每次比较的所选范围只允许结构或数据一种类型，引擎在打开数据库前拒绝混合请求。先列出表名，只有选中的表才读取结构 / 数据。数据模式按每个目标的实际元数据判断缺表，记录到 `TargetPlan.skippedTables`，不生成变更；其他目标中存在的同名表继续比较。源库在一个一致性读事务中获取所选快照，同一份快照供全部目标复用；各目标独立读取并计算。结构按语义定义和字段顺序比较；匹配键按 MySQL 排序权重判断唯一与相等。目标数据通过参数化 SQL 写入，脚本采用标识符转义和 UTF-8 / 二进制字面值生成。

新生成的数据脚本在 `INSERT` 值、`UPDATE SET` 赋值和 `WHERE` 条件中将普通字符串写为 `'文字'`，
单引号加倍转义，不添加字符集前缀或排序规则。导出脚本头统一设置 `SET NAMES utf8mb4`，
客户端连接由 JDBC 驱动使用 UTF-8。含反斜杠或控制字符的值继续使用 UTF-8 十六进制 `CONVERT` 表达式，
保持两种 `NO_BACKSLASH_ESCAPES` 设置下的值一致；二进制字段保留 `X'…'`。
`WHERE` 保留空值安全的 `<=>`，字符串按字段自身排序规则匹配，与客户端参数化数据写入一致。
执行前状态复验、锁内复验和回滚冲突核验继续使用完整行及摘要，不依赖字面量排序规则证明状态。
历史计划与档案保留原始 SQL，不因显示形式调整而重写。

依赖、不可支持对象和无法恢复风险在计划阶段阻止。高风险项不自动选择。目标地址、用户、SSL、证书路径与数据库范围绑定在计划中，执行、核验和回滚使用同一份已校验配置打开连接。配置改变时旧计划拒绝操作；连接名称和分组变更不影响绑定，密码不写入计划。执行读取服务器保存的计划 ID 与勾选项，不信任渲染进程提供的可执行 SQL。

## 执行

虚拟线程调度器控制目标并发与服务器串行。执行前重验结构 / 数据摘要；被引用表纳入锁范围。工具不在目标数据库创建任何备份表、凭据表或快照表：删除字段或改字段定义需要恢复原值时，在锁内读取该表数据（每表上限 20,000 行），绑定原结构计算恢复摘要，并在变更前持久化到本地 SQLite 和档案。成功读取的空表也有明确证据。普通读取、序列化或持久化失败会停止该目标；超限的表保留需人工恢复标记，无主键的有损字段操作继续按计划规则阻止。DML 按批次事务提交，每步先持久化 IN_FLIGHT，再以实际提交结果写 DONE；DDL 独立记录。每目标保留实际完成项、字段原值恢复资料、实际执行后行与表摘要。

## 回滚

回滚依靠本地恢复资料、实际完成证据、当前状态检查和逆向 SQL。MySQL DDL 隐式提交，不能保证整体事务回滚；恢复字段定义后逐行写回原值时，中途失败也可能只完成部分恢复。历史记录仍兼容其目标库备份表。

| 同步操作                       | 逆向恢复                                   |
| ------------------------------ | ------------------------------------------ |
| 新增／更新／删除行             | 删除新增行／恢复修改字段原值／重新插入原行 |
| 新建表／新增字段               | 删除本次创建的表／字段                     |
| 删除字段                       | 恢复原定义和位置，再按主键写回原值         |
| 修改字段                       | 恢复原定义，必要时按主键写回原值           |
| 索引、外键、注释、字符集等变化 | 对应逆向 DDL，恢复原定义                   |

1. 预览只纳入可信证据中已完成且尚未成功恢复的项；执行中、档案已清理、恢复记录本身及状态不明的项不能自动回滚。
2. 数据新增／更新要求实际执行后完整行仍一致，删除要求原匹配键未被后续写入占用；行冲突只阻止对应项。结构恢复按表组合，要求当前结构与整表数据摘要符合执行后状态，同表相关恢复项须选齐。
3. 验证计划连接绑定、恢复资料与摘要、旧备份和外键影响。同步成功不保证完整可回滚：原值采集超限、资料缺失或不可信的项仍需人工恢复，不关闭外键检查绕过风险。
4. 执行入口重新预览，锁内再次核验状态与资料，按反向顺序执行逆向 SQL，逐项记录 `IN_FLIGHT`／`DONE`，数据恢复检查影响行数。不能只依赖之前的预览。
5. 生成以 `parentId` 关联原记录的恢复记录，保留实际结果与恢复后摘要。总记录失败不抹去前面已完成的步骤；部分恢复后只依据最新可信证据继续剩余项，已恢复项不重复执行。恢复记录不能再次反向执行，需要重新比较。

疑似数据丢失先保留 SQLite、原记录与恢复档案，不反复执行掩盖未知状态。只保存结构脚本而未采集字段原值时，外部执行后不能自动找回删除或有损转换的字段内容。

## 外部执行

保存包以目标库分组，完整差异、同步和回滚脚本分开，不在目标库写入备份或收据对象。外部登记记录用户声明的执行范围；校验对照当前状态与选中变更。它们是原记录关联证据，不把“未执行”原始状态改写为工具成功。

新记录以 `LOCAL_V1` 标识恢复方式。原始 `04_rollback.sql` 保留生成计划时的内容；执行前完成采集后，按目标追加不可变的 `recovery.json` 和 `05_rollback_local.sql`。后者包含完整已选计划的逆向 SQL，不证明全部步骤已经执行；部分失败或中断后不能直接整份执行，使用前须核验实际完成范围。回滚预览和锁内执行都校验本地资料摘要，缺少原值的项不能自动恢复。旧记录和旧外部执行继续读取并核验其既有备份、收据及执行后快照，不创建新辅助对象。

## 本地备份

使用 SQLite VACUUM INTO 获取数据库快照，再打包档案。恢复先校验 SQLite、路径和解压范围，暂存后切换引擎资料，重写可迁移档案路径。ZIP 解压拒绝目录穿越并限制总大小。备份不含 Windows 密码材料。

## 数据库适配器与 PostgreSQL 事务

数据库类型和 JDBC 驱动分别管理。`Database` 保留公共连接、凭据及兼容入口，
`DatabaseAdapter` 定义专有元数据、版本和键语义契约；`MySqlAdapter/MySqlPlanner` 保留既有
MySQL 行为，`PostgresAdapter/PostgresPlanner` 生成 PostgreSQL 操作。`PostgresSql` 从元数据
生成类型、标识符、注释、索引、空值比较和结构化外键 SQL，不翻译 MySQL SQL 文本。

Electron 从随应用发布的目录下载并校验 PostgreSQL JDBC，临时文件同步后原子切换；Java 再次
检查摘要和路径，通过独立加载器实例化固定驱动，显式建立连接。驱动缓存在资料目录的
`drivers/<id>/<version>`，不进入业务备份。当前 MySQL 驱动仍随安装包分发。
升级目录必须保留仍被连接或历史恢复记录引用的版本条目和文件，不自动升级连接，不热卸载。

PostgreSQL 来源使用可重复读事务，所选快照供全部目标复用。确定性键按原值比较，numeric
标度和定长字符尾部空格规范化；字段类型及排序规则不兼容时阻止数据同步。

每个 PostgreSQL 目标的选中变更在一个事务内执行。现有表及引用依赖按固定顺序取得表锁，锁内
重新读取支持状态与目标快照，采集并持久化字段原值资料后才开始写入。缺表创建不使用
IF NOT EXISTS，并与所选后续 DDL 同事务。步骤先保存 IN_FLIGHT；全部 SQL、执行后行和摘要
采样完成后提交，确认提交后才保存 DONE。事务中途失败回滚前面步骤；提交或本地完成证据
保存结果不明时保留 UNKNOWN，不根据当前状态补写成功。MySQL 仍使用原独立 DDL／批次提交模型。

PostgreSQL 恢复仍要求可信完成步骤、当前执行后状态、本地资料摘要和外键核验。预览后在事务锁
内再次复验，按逆序恢复并生成 parentId 关联记录。删除字段的恢复先追加允许空的新字段、写回
原值，再恢复默认值和非空约束；不保证恢复原物理字段位置。结构摘要按语义字段排序，原始
元数据和归档仍保存实际顺序。外部执行声明和当前核验仍是追加证据，不改写原未执行事实。
