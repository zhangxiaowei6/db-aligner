# 性能排查与显示保护

按显示、列表、通信和引擎热点定位问题；日期性测量原文见[历史性能分析](../archive/legacy-client/migration.md#2026-10-11-至-2026-10-12-性能分析)。历史缓存策略不作为当前要求，实际测量见[验证记录](../validation/README.md)。

## SQL 显示与完整内容

`SqlView` 每页约 32,768 个 UTF-16 字符，边界避开代理对和 CRLF。大脚本使用纯文本，小脚本高亮最多 2,000 个片段，超限退回纯文本。分页可能拆开语句，仅用于阅读；复制、保存和执行使用完整原文。

执行确认只挂载当前目标脚本，完整目标摘要保持可见。历史记录当前页签按目标依次加载并展示全部脚本，每段独立分页、复制、失败重试，05 优先于 04；切换记录或页签隔离过期响应。其内存随全部目标 SQL 总量增长，需要测量，不能描述为单目标缓存。

入口：`desktop/src/components/SqlView.tsx` 与 `desktop/src/controller.tsx`。

## 列表与选择

连接树、差异及回滚长列表只挂载视口附近节点。差异／回滚超过 200 个分组或叶节点启用虚拟表格；分组选择覆盖完整筛选范围，不限当前挂载节点。范围选表通过“已选表”筛选查看完整选择，不再用历史标签清单方案。

连接树每次展开重新查询，刷新失败保留最近成功数据；分组本地展开与数据库查询的反馈时长分别处理。筛选不改变实际选择，页面和详情切换保留不相关滚动。现行参数见[交互规范](interaction-guidelines.md)。

## 通信与进程

Java `EngineMain` 经 `Json.presentation` 构造完整展示 JSON；Rust `desktop/src-tauri/src/engine.rs` 的独立 stdout 读取线程按行读取并用 `serde_json` 解析，再关联响应或转发事件。宿主事件由 `host.rs` 发送到受限前端桥接。

大结果仍需测量响应字节数、Java 展示转换、Rust 解析、事件传输和进程峰值内存，再决定是否拆分响应。精确数值展示转换不能改变原始计划、归档、摘要或 SQL；此处仅核对实现路径，没有执行性能压测。

## 引擎热点与后续测量

| 入口                                        | 需要核对的增长路径                                           | 测量或改进边界                                        |
| ------------------------------------------- | ------------------------------------------------------------ | ----------------------------------------------------- |
| `Service` 计划映射、`Comparisons`           | 比较快照和成功计划累计；终态比较任务十分钟淘汰不等于计划释放 | 单独设计计划失效，保护未保存计划                      |
| `Store.recordSummaries`                     | 先读取完整记录再去除大型行证据，仍有解析峰值                 | 评估摘要投影，兼容旧内嵌计划和恢复格式，不删原资料    |
| `Service.record.get`、`Store.events`        | 完整详情、恢复资料与事件反复传输                             | 评估摘要／增量事件，核验只追加证据                    |
| `Service.schemaExport`、`Database.snapshot` | 多表元数据往返和整包对象                                     | 测量读取耗时，保留完整 SQL、外键后置和 DROP 语义      |
| `Database.keyTokens`、`Planner.data`        | 键读取与多目标源索引构造                                     | 保留重复键、排序规则和比较期间变化校验                |
| `Jobs.persist`                              | 步骤和大型恢复资料持久化                                     | 保留写入前 IN_FLIGHT、原值先落盘、FULL 同步与提交事实 |

Java 入口位于 `engine/src/main/java/io/dbaligner`。上述为当前源码检查与待量化方向，不是本次性能故障或已实现优化。引擎或协议改动按对应技能验证，不能用显示预览证明真实数据库安全。

## 验收方法与边界

命令见[测试指南](../development/testing.md#浏览器与原生界面)。性能专项使用生产前端、虚构表和内存桥接，包含 298／1,000／5,000 表、10 MiB 单行 SQL、20,000 项差异和恢复列表，不连接数据库。

关注响应到达后显示、翻页、筛选和选择耗时、SQL 字符数、DOM 节点及 GC 后堆内存。既有显示目标为首次小于 1 秒、翻页小于 200 ms、20,000 项筛选和选择小于 500 ms；这些不是生产数据库耗时保证。`docs/performance-ui-qa.json` 保存最近一次机器结果，可被后续覆盖。

前端生产包存在体积提示，冷启动解析和长期原生进程内存需独立测量。展示分页或虚拟滚动不能降低引擎读取量，也不能绕过每表 20,000 行安全上限。
