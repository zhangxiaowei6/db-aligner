# 0.1.0 支持范围与限制

## 已实现

Windows x64 桌面程序；MySQL 5.7 / 8.0 / 8.4 普通 InnoDB 表；按工作区管理连接、会话导入、结构查看、指定多表及多目标比较、字段 / 常规索引 / 外键 / 注释 / 字符集与排序规则变化、基础数据新增更新删除、业务和复合键、脚本归档、执行、版本标记、外部校验、回滚及本地备份。

## 首版保护边界

- 数据同步面向基础字典等小表，每张表最多 20,000 行，超限阻止读取后同步。不是全量迁移、CDC 或大表增量复制工具。工具不在目标数据库创建备份表、凭据表或快照表；字段原值恢复资料在执行前锁内读取并保存在本地记录，同样受 20,000 行上限约束，超限或无主键的表在回滚预览中标记为需人工恢复。
- 视图、分区、触发器、生成列、CHECK、函数索引 / 不可见索引等复杂对象没有可靠迁移与恢复支持，会阻止同步。不能通过导出的 SQL 自动保证跨版本高级语法兼容；普通表才进入工具执行。
- 主键结构变更、缺少可靠恢复键的有损字段操作、受外部外键依赖影响的数据删除 / 被引用键更新，采取保守阻止策略。不会自动重映射关联表的外键 ID，也不会关闭外键检查绕过约束。
- 每次只能比较和同步结构或数据，不能混合（不同表也不能混合）。数据模式只处理源目标都存在的同名表，缺失目标表按目标库自动跳过，不建表、不生成该表的数据变更。字段不兼容时仍要求先同步结构，再重新比较数据；结构模式创建缺失表后需另发起数据同步。
- 数据匹配使用服务器排序规则的权重判断键，空键或重复键阻止同步；源目标匹配键排序规则不一致时要求调整后重新比较。业务键更新保留目标主键。
- 回滚要求实际执行证据和匹配的执行后状态，字段原值类恢复还依赖记录内保存的恢复资料（历史记录兼容其目标库备份表）。结构恢复按表组合；数据恢复允许独立行，但后续行修改、外键影响等冲突会禁用对应项。
- 强制结束程序可能处于“已提交但确认未落盘”的窗口。重启将正在执行记录标为中断并保留证据，核验追加结果；执行范围或恢复证据不明的项不能自动回滚。新表创建后立即中断等情形需人工核实。
- 外部 SQL 执行受使用工具是否遇错停止、维护窗口和其他并发写入影响。必须登记实际执行范围并通过当前状态核验，才能进入工具回滚；当前状态符合预期不能替代历史证明。
- 不支持 SSH 隧道、云 IAM 登录、代理动态认证，或连接 MySQL 以外的服务器。Navicat 加密密码、DataGrip 外部凭据库不解密；导入 SSL / SSH 等专有参数需人工复核配置。
- Windows 10 / 11 干净机器安装、双向 SSL 客户端证书、各厂商所有历史版本的真实会话导出还未完成验收。当前真库及打包测试范围见验证记录。
- 安装包未签名，无自动更新。源码已准备 Apache-2.0 和第三方材料，尚未创建远程开源仓库或发布 Release。

## 权限与资料

客户端不创建业务数据库账号或自动授权，也不在目标数据库创建备份、收据或快照等对象。执行连接需具备读取、所选 DDL / DML、LOCK TABLES、相关被引用表读取等实际权限；权限不足会按目标记录失败。请使用已有测试库账号验证后再用于其他环境。

密码文件使用 Windows 系统加密，SQLite 普通配置不含明文密码。SQL、行快照、执行日志、归档和本地备份可能含业务数据，保存在用户选择的本机目录。配置导出排除凭据和证书路径，备份不迁移密码。应用不会上传这些资料；开源提交前应检查忽略规则与文件内容。
