# 历史迁移与性能说明

2026-10-17 从现行文档移出，保留来源与原文。以下技术栈、命令及性能策略仅表达当时情况。

## 版本记录中的迁移说明

本文件从 Tauri 客户端重新记录面向使用者的版本变化。旧 Electron 版本与本客户端的安装、资料和更新签名不兼容；旧版验证过程保留在[验证记录](../../validation/README.md)。

### 0.1.0 - 2026-10-16

#### 新增

- 发布 Windows x64 Tauri 2 客户端，继续提供 MySQL 5.7／8.0／8.4 与 PostgreSQL 17.x 的结构及基础数据比较、预览、执行、核验和本地恢复。
- 继续提供工作区、连接分组、同步模板、版本归档，以及浅色、深色和跟随系统主题。
- 提供带 Java 运行时的 NSIS 安装包与完整便携 ZIP。安装版通过签名更新包获取后续正式版本。

#### 改进

- 新客户端使用独立安装及资料目录，旧 Electron 安装、密码和本地资料不迁移或删除；旧版用户需手动安装并重新配置。
- 使用 Windows 原生标题栏；修复减少动态效果设置下弹窗退出后遮挡页面的问题，并增加页面切换动画。
- PostgreSQL JDBC 驱动仍按需安装；内置 MySQL 驱动可供离线使用。

#### 兼容与限制

- 新旧客户端不能通过旧 Electron 更新机制互相升级。首次 Tauri 发布后的真实自动更新需要后续递增版本验证。
- 基础数据每表最多 20,000 行；高风险结构变更默认不选，具体范围见[支持范围](../../guide/limitations.md)。
- 浏览器预览只使用内存虚构数据，真实连接与同步须使用桌面客户端。

本版的本地与 GitHub 构建、真库及界面检查结果见[验证记录](../../validation/README.md)。

## 发布文档中的迁移沿革

真库使用 `.tools/mysql-test` 中的 5.7.44／8.0.45／8.4.8 和 `.tools/postgresql-test` 中的项目隔离 17.x，分别绑定 `127.0.0.1:33957`、`33980`、`33984`、`33917`，不注册服务。每个工作流在自己的 runner 内串行启动 UI 与真库测试，结束或失败都分别调用两种数据库的项目停止脚本。PostgreSQL 打包客户端验收包含首次驱动下载、重启后缓存复用，以及同一进程内 MySQL／PostgreSQL 双驱动连接。新的原生客户端报告使用 `docs/native-client-smoke-result.json`、`docs/postgresql-native-client-smoke.json` 和 `docs/postgresql-native-client-cached-smoke.json`；旧 Electron 报告保留为历史证据。报告与多数据库截图保存为独立的验收 Artifact；不会上传测试凭据、SQL 档案或数据库资料。

旧 Electron 发布使用过 `v0.1.0`、`v0.1.1`、`v0.1.2` 和 `v0.2.0` 标签，其中后两个曾公开为 Release。Tauri 客户端与旧版的安装、资料和更新签名不兼容，因此新系列从 `v0.1.0` 重新编号。按维护者要求删除旧 Release 与标签，但保留 Git 提交历史及[验证记录](../../validation/README.md)中的原始日期、构建和验收范围。旧版用户需要手动安装新版并重新配置；旧版的本地资料不会被删除。

- 在干净 Windows 10／11 x64 环境安装 Tauri NSIS 包，验证无需系统 Java／Maven；缺少 WebView2 的电脑在首次安装时可联网获取运行时。未配置 Windows 代码签名时可能显示未知发布者提示。[Windows 安装器与 WebView2 模式](https://v2.tauri.app/distribute/windows-installer/)见官方说明。
- 在隔离测试资料目录完成两个新版客户端版本之间的覆盖升级，检查连接、系统加密密码、主题、SQLite、记录与恢复档案仍可使用；确认旧 Electron 安装与资料保持独立，不执行迁移。
- 用两个递增的正式版本验证发现、下载、签名校验、取消安装、确认重启、安装及资料保留。草稿／预发布不能被正式客户端发现。有运行、排队或取消中的任务时必须拒绝安装，原任务继续运行。
- 无需安装 ZIP 必须完整解压，包含程序、Java 引擎、运行时与许可材料；升级先关闭客户端，再替换完整程序目录。自动更新验收针对 新版 NSIS 安装版。
- 网络无法访问 GitHub时，用户可下载正式安装包手动覆盖安装。更新检查失败不阻塞数据库功能。

## 2026-10-11 至 2026-10-12 性能分析

### 2026-10-12：历史脚本展示调整

按当前交互要求，记录详情的执行与回滚脚本加载当前页签全部目标的脚本及清单，
按目标依次展示，取消目标库下拉选择。每段仍使用 `SqlView` 的分页、节点数量限制和完整复制；
保留独立加载错误、重试、05 优先于 04、旧档案标签及记录／页签过期响应隔离。
历史脚本的内存占用随当前页签全部目标的 SQL 总量增长，不再采用下述历史验收中的单目标缓存策略。
执行确认弹窗仍按目标切换脚本，完整目标摘要保持可见。

### 2026-10-11：SQL 预览与大清单

本次报告针对约 298 张表生成结构 SQL 后的界面卡顿。排查使用当前源码与虚构压力数据，
不读取生产 SQL、用户 SQLite 或恢复档案，不连接生产数据库。

#### 已修复的界面热点

- `desktop/src/components/SqlView.tsx` 原先对全文正则分词并为每个片段创建 React 节点。
  298 张表、每表 30 字段的模拟输入约 59 万字符，原实现产生 145,424 个 span；
  只读 React 服务端渲染约 651 ms，不包含浏览器挂载、布局和绘制，也不是生产复现。
- SQL 每页约 32,768 个 UTF-16 字符，边界避开代理对与 CRLF；大脚本不高亮，
  小脚本高亮最多 2,000 个片段，超限使用纯文本。分页可拆开语句，仅用于阅读；
  复制、保存文件与执行计划继续使用完整原文，不按显示页截断。
- 执行确认只为当前目标构造和挂载脚本，目标摘要仍显示完整范围。
  历史脚本只加载当前目标的脚本及对应清单，切换后丢弃旧 SQL 缓存，
  保留旧档案标签、05 优先于 04、重试及过期响应隔离。
- 差异和回滚分组改为一次遍历建索引；超过 200 个分组／叶节点时使用虚拟表格。
  父节点统计自下而上计算，选择与缺表查询使用 Set；筛选不改变执行选择，
  分组勾选覆盖筛选后的完整范围。大量已选表只展示前 20 个标签，全部表名可分页查看。
- 未变化的 SQL、分组和统计复用计算；范围签名只在相关字段变动时重新计算。

| ------ | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |

| 高     | `Store.recordSummaries()` 先 `list("record")` 解析完整记录，再移除 `rowAfter`／`recoveryRows`                                         | 记录多或恢复资料大时，启动和每次状态刷新仍有读取／解析峰值。评估 SQLite 摘要投影或独立摘要，兼容历史内嵌计划与旧恢复格式；不删除原资料。    |

| 待测   | `Service.record.get` 返回完整计划、恢复资料和全部 `Store.events()`；任务事件触发前端刷新详情                                          | 长时间执行或大量历史事件导致反复传输。评估只读摘要／增量事件接口；核验只追加证据，不能改写原执行事实。                                      |
| 待测   | `Service.schemaExport()` 逐表调用 `Database.snapshot(..., false)`，读取多个元数据结果并保留全部表对象                                 | 表多或数据库往返慢时生成耗时增加。评估专用导出读取与元数据复用，检查建表语句、外键后置与 DROP 选项输出一致性。                              |

#### 验收方法

先运行根目录 `npm run build`，再运行 `npm run qa:ui -w desktop -- --performance`。
该入口使用生产前端资源和内存虚构桥接，覆盖 298／1,000／5,000 张表、10 MiB 单行 SQL、
20,000 项差异和恢复列表；不执行数据库操作。最新机器测量保存在
[性能 UI 报告](../../performance-ui-qa.json)，它会被下次运行覆盖，不是不可变历史快照。

主要指标为响应到达后显示时间、翻页、筛选与选择时间、当前 SQL 字符数、挂载节点数、
GC 后浏览器堆内存。验收目标：首次 SQL 显示小于 1 秒，翻页小于 200 ms，
20,000 项筛选和选择小于 500 ms；长列表只挂载视口附近的行。
实际环境、通过结果与限制以 [验证记录](../../validation/README.md) 为准。
